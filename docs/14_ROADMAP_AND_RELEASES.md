# 14 — Roadmap and Releases

Roadmap is outcome- and evidence-led. Dates are intentionally omitted until scope, participant availability, and dependencies are known.

## Phase 0 — Problem discovery

**Objective:** identify a specific recurring and consequential workflow.

Deliverables:
- competitor/source register;
- participant recruitment log;
- completed discovery interviews;
- evidence synthesis and counter-evidence;
- refined target segment and problem statement.

**Exit gate:** a clearly evidenced problem and a plausible product intervention.

## Phase 1 — Product definition

**Objective:** specify the smallest coherent workflow.

Deliverables:
- validated personas / JTBD;
- prioritised opportunity solution tree;
- PRD and acceptance criteria;
- metric definitions and guardrails;
- low-fidelity user journey.

**Exit gate:** requirements trace to actual user evidence.

## Phase 2 — Prototype

**Objective:** test whether the workflow is understandable and useful.

Deliverables:
- operator dashboard prototype;
- minimal exception workflow;
- synthetic-data disclosure;
- usability test plan and findings.

**Exit gate:** target users can complete core tasks, and critical misinterpretations are resolved.

## Phase 3 — Pilot readiness

**Objective:** determine whether a controlled pilot is safe and feasible.

Dependencies:
- willing operator and accountable sponsor;
- access permissions and data agreements;
- clear baseline and success criteria;
- integration and security review;
- operational fallback plan.

**Exit gate:** pilot is authorised and success / guardrail measurement is agreed.

## Phase 4 — Controlled pilot

Only after the prior gate. Record deployment context, adoption, data completeness, operational outcomes, confounders, and limitations. Report results only with permission and an auditable method.

## Prioritisation framework

Score candidate work using:
- customer pain severity and frequency;
- confidence in evidence;
- expected outcome contribution;
- reach within the target segment;
- engineering and integration effort;
- operational and safety risk;
- reversibility / learning value.

A scoring framework informs discussion; it does not replace judgement.
