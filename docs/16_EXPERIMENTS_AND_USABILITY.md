# 16 — Experiments and Usability

## Research-to-prototype sequence

Do not begin with polished screens. Start with a workflow sketch or paper prototype after the discovery stage identifies the user and task.

## Riskiest assumptions

| Assumption | Experiment | Signal |
|---|---|---|
| Dispatcher cannot establish readiness quickly | Observe / reconstruct shift preparation | Time, steps, uncertainty, workarounds |
| Fragmentation causes meaningful delay | Map information sources and recent exceptions | Manual reconciliation and consequences |
| Exception ownership is unclear | Review recent issue lifecycle | Unassigned work, handoffs, time to action |
| A consolidated view is useful | Test low-fidelity board with real workflow examples | Correct interpretation and task performance |
| Driver input is necessary | Compare existing data sources and driver workflow | Incremental value vs added burden |

## Usability task examples

1. Find all vehicles scheduled for the next shift.
2. Identify vehicles whose readiness is unknown and explain why.
3. Find the oldest unresolved exception.
4. Assign a blocker to the correct owner.
5. Explain whether a vehicle is ready when its last status is stale.
6. Export a shift summary and interpret the denominator.

## Measures

- task completion / failure;
- time on task;
- critical errors;
- assistance required;
- incorrect readiness interpretation;
- confidence and rationale;
- qualitative friction.

Set success thresholds before sessions. A small usability sample is useful for identifying issues, not statistical proof of broad usability.

## Test disclosure

Prototype status, synthetic data, and non-integrated screens must be disclosed to participants. Do not simulate real-time vehicle connections in a way that could be mistaken for production functionality.
